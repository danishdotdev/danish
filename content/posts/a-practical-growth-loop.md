## Start with value, not virality

A growth loop is not a clever referral button attached to the end of a product. It is a repeated cycle where a useful outcome creates the next opportunity for someone to discover, use, or benefit from the product.

The distinction matters for a new product. If the core experience is not useful, a loop only spreads disappointment faster. The first question is always: what result makes an existing user want to continue, share, invite, or create an artifact that reaches another person?

The [Reforge explanation of growth loops](https://www.reforge.com/blog/growth-loops) is a helpful framing: unlike a one-way funnel, a loop creates inputs for its own next cycle. For an early team, that makes the product outcome the most important growth asset.

## Find the natural output of the workflow

Look at the work the product helps someone complete. Does it naturally create something another person needs to see, approve, use, or contribute to?

Examples of possible loop inputs:

- a shared summary that invites a teammate into the same workspace;
- a project artifact that makes the product visible to a collaborator;
- a useful report that starts a conversation with a new stakeholder;
- a customer success story that gives another person a reason to ask how it was done.

Not every product needs a social loop. A B2B product may grow through a new department being invited into a workflow. A tool for independent professionals may grow when a polished client-facing output creates a credible reason to ask about the tool behind it.

## Draw the loop in one sentence

If the loop is real, you should be able to describe it plainly:

> A user gets _this outcome_, which causes _this new person or action_ to enter the product, which helps create the next outcome.

For example: “A consultant turns a client call into a clear shared follow-up; the client receives it, collaborates on the next steps, and the consultant uses the workspace again for the next meeting.”

The sentence exposes weak links. If the new person has no reason to engage, the loop is not complete. If the initial outcome is not valuable, there is nothing worth sharing. If the next use depends on a manual reminder from the founder, it may be a good sales motion but not yet a product loop.

## Choose one measurable link

New teams do not need a full growth dashboard to test a loop. Pick the link that is most uncertain:

- How many completed workflows create a shareable artifact?
- How many recipients open it?
- How many recipients become active collaborators?
- How many active collaborators return and create another outcome?

Then make one improvement to that link. A clearer invitation, a more useful shared output, or a smaller setup step can teach more than a broad campaign with too many variables.

## Do not force the loop

Forced invitations, spammy incentives, and features that exist only to expose branding may create short-term numbers while weakening trust. The best loops feel like a natural extension of the work someone already wants to do.

That is why the product’s core value comes first. When an outcome is genuinely useful, sharing and collaboration have a reason. When it is not, no growth mechanic can manufacture one for long.

## Build the first loop around a narrow use case

Early on, keep the loop tied to one concrete job and one defined group of people. It is easier to see why it works, easier to fix, and easier to explain. Once it reliably produces value, you can ask whether the same pattern applies to adjacent use cases.

Growth loops compound only when the product keeps earning the next action. Start there, and the loop becomes a system rather than a slogan.
